DIY OID 点读手册与 A4 Sessions

把自己的学习内容做成可打印、可点读、可长期增量维护的纸质 Session。这里从笔、音频和辅码的关系讲起，一直讲到装笔、打印、实体测试与故障回滚。

Start here

第一次使用：只做这 6 步

先用一张小型诊断页闭环，不要一上来打印整本。目标是确认“笔里有包、纸上码可读、码与声音对应”三件事。

1

准备文件

确认本地已有同一版本的 A4 PDF、GME、稳定编码表和音频源映射。不要只拿一份 PDF。

2

把 GME 放进笔

用笔身的数据口接 Mac，把 GME 复制到笔的根目录，然后安全推出。不是复制到底座，也不是通过蓝牙。

3

打印诊断页

使用“实际大小 / 100%”，关闭“适合页面”和省墨。先打印包含已知可用控制码、START 和几个普通码的一页。

4

激活一次，再点控制码

若尚未切到这套内容，先点 3×3、22 mm 的 START；随后点已知可用的 listo 控制码。笔已经处于同一 Product 时，重复点 START 可能不重播，不能单独用它判断打印成败。

5

逐项打勾

在纸上标记“响 / 不响 / 声音不对”，记录打印机、纸张、缩放和质量设置。一个类型重复出现，不等于多个独立样本。

6

通过后再批量

小页通过后再打印完整 Sessions。发现问题，先回滚到上一个已通过版本，不要同时改音频、编码和排版。

30 秒决策树

整张都不响

先看笔是否识别普通官方内容 → GME 是否在笔根目录 → 是否存在同 Product ID 的另一包 → 安全推出后重启再测。

大多数响，少数不响

GME 已基本加载。查该码是否被缩放、污损、切边或映射错；换同音频的新 OID 做 A/B 复测。

响了，但声音不对

停止继续打印。对照稳定编码表、YAML 与 source map；这通常是映射/版本问题，不是纸张问题。

01 · Mental model

四个组件，缺一不可

点读不是“PDF 里嵌了声音”。纸、码、包和笔在使用时是四个分离的对象。

① 纸面内容

文字、图片、题目与学习步骤。它决定人看到什么，但不直接储存声音。

② OID 辅码

打印在纸上的微点阵。笔的光学传感器读出编号，再去包内寻找对应脚本。

③ GME 音频包

放在笔内存根目录的文件，包含 Product ID、OID 脚本和音频。它决定“这个码播放什么”。

④ 兼容点读笔

负责识别 OID、读取 GME 并播放音频。兼容性必须以实际型号与成品纸测试。

笔尖读取纸上 OID→识别 Product / Script Code→在 GME 中查脚本→播放对应音频

判断是否已加载成功：只要同一自制包中的多个普通脚本码能稳定播放，就说明笔已经能够读取该 GME。START 的单独异常不应推翻这个事实。

02 · Connection boundaries

00110：笔、底座、USB、Wi‑Fi 各自做什么

这里最容易混淆的是“底座能联网”与“本地文件能经 Wi‑Fi 传入”。它们不是同一件事。

00110 的范围：这是第四代笔。Ravensburger 官方称它兼容全部官方 tiptoi 产品，CREATE 系列除外；DIY GME 不属于这项官方兼容承诺。本项目只能确认：这支 00110 在首轮测试中让 42 个打印位置里的 35 个实际出声，最终整册仍待重新打印验证。

通道 / 部件适合做什么不应假定能做什么本手册结论
笔身 USB 数据口让 Mac 把笔识别为外接存储；复制官方或 DIY 的 GME；充电（视线材/电源而定）。不是所有 USB 线都传数据；只有充电功能的线不能完成复制。本地 GME 的正确入口
充电底座的接口给底座供电、给笔充电，并配合官方 Wi‑Fi 下载流程。不要把它当成 Mac 上的通用 U 盘接口；不要通过它拖入 DIY GME。官方生态用途
底座 Wi‑Fi按官方设置流程连接家庭网络，为官方书籍获取音频。不是通用文件服务器；本工作流不使用它上传本地音频或 DIY GME。官方音频下载

官方路径

官方书籍音频

  • 从 Ravensburger 官方音频页面 / tiptoi Manager 获取。
  • 可经笔身 USB 复制；配套充电底座则可按官方流程联网下载。
  • 官方页面、说明书和底座指示灯定义优先于本手册摘要。
  • 适用于有官方产品编号与官方音频包的书籍。
DIY 路径

自己的固定音频

  • 将已取得权利的文本/录音/TTS 做成 tttool 项目。
  • 生成 OID 页面和 GME，并保留稳定映射与源文件。
  • 用数据线直接连接笔身，把 GME 放在笔根目录。
  • 离线点读；不依赖底座 Wi‑Fi，也不经蓝牙上传。

底座联网的简单识别：按官方说明完成配网后，绿灯表示当前有活动 Wi‑Fi 连接，红灯表示无法连接互联网。不同阶段/固件的灯光行为以官方底座设置页和底座 FAQ为准。绿灯不等于某次官方音频必然下载成功，更不证明底座能接收自制文件。

底座第一次连接家庭 Wi‑Fi

  1. 给底座接上随附电源，把已开机的第四代笔放入底座；快速连按 WLAN 按钮两次，按钮应呈橙色并进入设置状态。
  2. 在手机、平板或电脑的 Wi‑Fi 列表中选择名称以 tiptoi_ 开头的临时网络。系统提示“没有互联网”时仍选择保持连接。
  3. 打开浏览器，在地址栏输入 http://192.168.1.1/，选择家庭 Wi‑Fi，输入密码并保存。路由器必须提供 2.4 GHz 网络。
  4. WLAN 按钮常亮绿色表示连接成功；红色表示未连上。需要重设时，可再次快速按两次进入设置；长按约 10 秒会清除底座保存的网络资料。
  5. 下载官方书籍音频时，先用笔点该官方产品的注册标志，等待提示完整播放，再把笔放回底座。绿色环分段显示进度；完整闭合后下载完成。

仍然不用于本地上传：上面这套 Wi‑Fi 流程只把底座接入 Ravensburger 的官方下载服务。自己的 MP3 或 DIY GME 仍须先在电脑上构建，再经笔身 USB 数据口复制。

03 · Install on macOS

在 Mac 上把 GME 复制到笔根目录

以下步骤同时适用于从官方页面取得的 GME 和自己构建的 GME；来源不同，文件落点相同。

  1. 先给笔充足电。构建完成后，确认待复制文件扩展名为 .gme，并记录版本与校验值。
  2. 把随笔附带的连接线插在笔身接口。另一端接 Mac；USB‑C Mac 可加可靠转接头。若 Finder 没出现新磁盘，先换 Mac 接口或转接头；改用其他线材属于非官方排障。
  3. 在 Finder 打开笔的磁盘。看到的是笔的存储根目录。不要进入新建子文件夹，也不要改动不认识的系统文件。
  4. 检查 Product ID 冲突。同一个 Product ID 只保留一个 GME。更新同一套西语包时，移走旧版后再复制新版；不要让两个同 PID 包并存。
  5. 把 GME 拖到根目录。等待复制真正完成。不要把 PDF、源音频或 YAML 一起塞入笔里；它们应保存在电脑的项目归档中。
  6. 在 Finder 安全推出。等磁盘消失后再拔线。随后重启笔，先用诊断页验证 START、已知控制码和两个普通码。

若 macOS 提示“无法读取磁盘 / 是否初始化”：不要格式化。取消操作，换线、接口或另一台电脑排查。格式化可能破坏笔内官方内容和文件系统。

“根目录”是什么：打开笔这个外接磁盘后首先看到的那一层，不是桌面、下载文件夹，也不是你另外创建的 audio 或 books 子目录。

04 · Print specification

打印参数：先守住“不缩放”

OID 是机器读取的图案。肉眼看起来“几乎一样”的缩放、重采样、压缩或墨点糊连，都可能改变识别结果。

项目正式建议原因 / 验证方式
纸张A4 白色哑光纸；先用普通 80–100 g/m² 测试避免高反光覆膜、纹理太深或底色过暗；最终以实体读码为准。
缩放实际大小 / 100%关闭“适合页面”“缩放到纸张”和应用层二次缩放。
OID 源图与打印质量OID 源图按 1200 DPI 生成；打印机选择最高可用质量关闭草稿、省墨、照片平滑、锐化和压缩。打印机标称 DPI 不等于 OID 源图 DPI，可靠性仍以成品纸为准。
普通 OID 图案--pixel-size 2，物理区域 15–18 mm这里的 2 表示每个微点由 2×2 个栅格像素组成，不是整张码只有 2×2 个点；不要在排版软件里拉伸图案。
关键 START--pixel-size 3，物理区域 22 mm，并留足白边关键入口使用更稳健的版式，且每本保留一个已知可用控制码。
摆放不贴裁切边；与文字、边框、图片保持净空避免订书钉、折痕、笔迹、胶带和深色背景覆盖微点阵。
批量前门槛先打 1 页诊断页并逐码打勾只要换打印机、纸张、驱动、导出方式或 PDF 版本，就重新小测。

05 · Build pipeline

从学习材料到可点读 A4 的完整流程

把流程做成可重复的发布管线。每一版都能追溯“纸上的码 → 脚本 → 音频 → 原始来源”。

1

定 Session 目标

每页只服务一个明确动作，例如辨音、跟读、回忆、场景表达或自测。先写“学完能做什么”。

2

锁定来源

为每段文本记录来源、权利状态、语言版本与校对状态。事实或考试材料还要记录页码/条款。

3

拆分音频

按最小可重复单位切片：词、短语、句子、小段、全文。避免一个码播放过长且无法定位。

4

规范音频

统一音量、声道和采样参数。当前已验证链路使用 Ogg Vorbis、22.05 kHz、单声道；保留无损或高质量源母版。

5

登记稳定编码

确定 Product ID，在 registry 中为每个内容分配永久名字和 OID。只追加，不重排、不复用。

6

写 tttool YAML

把产品、脚本、音频和播放顺序写入项目文件；生成/更新稳定 scriptcodes 与 source map。

7

生成 OID 与 GME

按最终 DPI 和 code-dim 直接生成图案，随后构建 GME。不要先做小图再在排版软件里放大。

8

软件 QA

运行 tttool 检查；验证 GME 可读、脚本数量、音频解码、重复编码、缺失文件、校验值和 ZIP 完整性。

9

A4 排版

放入 --pixel-size 2 普通码、--pixel-size 3 START、可见编号和复习步骤。保留净空，并导出为固定尺寸 PDF。

10

视觉 QA

逐页渲染检查：无遮挡、无越界、无空页、文字可读、OID 未被裁切或重采样，页码和版本一致。

11

实体 QA

100% 打印诊断页，点 START、控制码和新增码；记录响/不响/错音。通过后才打印全套。

12

发布与归档

网页可公开说明书与有权公开的 PDF；个人 GME 留本地。归档版本、校验值、构建记录和回滚包。

最重要的 QA 边界：lint 通过、GME 可解析和PDF 看起来正常都是必要条件；只有实体笔在实体纸上读出正确声音，才算最终通过。

06 · Stable identity

Product ID 与 OID：采用 append-only

纸会长期存在。只要旧编码被重新分配，旧纸就可能在新 GME 下播放错误声音。因此“稳定身份”比文件名漂亮更重要。

Product ID 是一本“产品”的身份

tttool 建议 DIY 项目在 900–950 中选值，但这不是全球保留区。一套持续更新的西语库选用 930；其他主题必须先用 tttool info 扫描本地和笔内 GME 后再分配。文件名不能证明实际 PID。

OID / Script Code 是一个动作的永久身份

例如 es_vocab_v001_word 一旦映射到某个数字，就长期保持。内容废弃时标记 retired，也不把数字给新内容。Product ID / START 是特殊码，不复用为普通播放脚本。

同一 Product ID 只留一个 GME

笔根目录若并存两个同 PID 包，读取结果可能不确定。升级时先备份并移走旧包，再复制兼容旧码的新包。

新版必须兼容旧纸

新版 GME 应包含所有历史有效脚本码。若某个纸面码物理表现不好，保留其映射，同时为同音频追加一个 replacement OID。

建议最小登记表

字段示例规则

如果丢失稳定编码表：先从旧 YAML、.codes.yaml、旧 PDF 和旧 GME 恢复映射，再继续新增。不要让工具自动重排后直接发布。

07 · Audio design

音频要能“点、跟、遮、想、验”

好的点读页不是把网页上的长音频搬到纸上，而是把学习动作切成可控制的小循环。

最小片段

一个词、音节、数字、法律要件或容易错的短语。适合重复辨音与校正。

组合片段

词组或完整句。用于连读、语调和从知识点到表达的过渡。

全文片段

一段对话或场景。适合先整体听，再回到小片段，最后复述。

提示与答案

先放问题/任务，答案音频与提示音频分开；让学习者先输出，再点读自检。

节奏与留白

速度清楚自然；练习型音频可在提示后留出回答时间。不要把所有指令塞进每段音频。

版本化源映射

每个 OID 记录原文、译文、音频路径、声音/生成方式、许可、日期和校对状态。

推荐学习循环：看懂 → 点听 → 跟读 → 遮住答案说出/写出 → 点答案自检 → 换一个场景迁移。一个 Session 结束时，必须有一次“不看答案的提取”。

音频发布前检查

  • 每段开头不被截断，结尾没有明显爆音或长静音。
  • 同一 Session 音量和说话人风格基本一致。
  • 文本、实际发音、页面标签与 source map 四者一致。
  • 专名、数字、重音和容易混淆的音已人工抽听。
  • 原始母版与投放版分开保存；GME 使用的是确定版本。
  • 第三方录音、书籍材料与 TTS 输出的使用权已经确认。

08 · Daily practice

怎么使用 A4 Sessions

每页是一段可以独立完成的学习回路，不追求一次点完所有码。建议在纸上直接留下日期、勾叉与一句反思。

1. 启动（30 秒）

首次使用或从别的产品切回时点封面 START；普通学习页点 listo 控制码确认包与纸匹配。再读出今天的任务，例如“能听辨 5 组音并说出例词”。

2. 输入（2–4 分钟）

逐个点最小片段；看文字听两次，再看口型/重音提示跟读。困难项画圈。

3. 组合（2–4 分钟）

点短语、句子或小段，把刚才的元素放回真实语流。

4. 提取（2–5 分钟）

遮住答案，只看中文、图片或问题，先说/写，再点音频核对。此步最重要。

5. 迁移（1–3 分钟）

替换人物、地点、数字或事实，造一个与自己有关的新句/新案例。

6. 收尾（30 秒）

只记录一个下次重点：发音、词义、规则还是提取速度。无需抄一整页笔记。

新增 Session 的安全流程

  1. 复制 Session 模板，写清目标、来源和版本；不要直接编辑已发布 PDF。
  2. 从稳定 registry 的最后一个号码之后追加 OID；不移动旧编号。
  3. 新增音频与 source map；抽听发音、数字、专名和开头结尾。
  4. 构建一个包含旧码 + 新码的新 GME；不要做只含新增页、却使用同 PID 的第二个 GME。
  5. 软件检查、逐页渲染、打印新增诊断页、实体点读。
  6. 通过后更新版本号、校验值、变更日志和回滚包，再打印正式页。

手写内容的限制：笔只能播放构建 GME 时已经固定映射的音频。后来随手写下的新句子不会自动获得声音；要点读它，必须先新增固定音频、分配新 OID、重建兼容旧码的 GME，并重新打印对应码。

09 · Troubleshooting

排错树：一次只改变一个变量

先判断是“设备/包层”“纸码层”还是“映射层”。同时改线材、GME 和排版，会让原因无法定位。

A. Mac 看不到笔

  1. 确认线插在笔身，不是底座。
  2. 换数据线、Mac 接口或转接头；充电成功不证明能传数据。
  3. 给笔充电并重启，再连接。
  4. 若系统提示初始化/格式化，取消，不要破坏原盘。

B. 自制页全部不响

  1. 先确认官方内容仍能播放，排除电量/笔本身问题。
  2. 确认 GME 在笔根目录、复制完整并已安全推出。
  3. 确认根目录没有两个同 Product ID 的 GME。
  4. 用同包的已知可用控制码测试；必要时回滚上版 GME。

C. 只有少数码不响

  1. 既然多数码响，先不要反复重装 GME。
  2. 查打印缩放、污渍、折痕、裁切、背景和点阵糊连。
  3. 在同页放已知控制码，换一台打印机/纸张做对照。
  4. 保留原 OID，为同一音频追加 replacement OID，做 A/B 测试。

D. 能响但内容错

  1. 立即停止继续打印，这不是“多点几次”能解决的问题。
  2. 对照页面可见编号、OID registry、YAML 与 source map。
  3. 检查是否误装旧版 GME，或同 PID 包同时存在。
  4. 恢复到校验值已知且实体通过的版本，再修映射。

E. START 不响，但普通码响

  1. 这说明 GME 很可能已经加载；tttool 自制包激活后，同一 Product OID 可能成为无动作码。
  2. 先点一本官方产品的启动码切换出去，再点本册 3×3、22 mm START；随后点 listo 控制码验证是否已经切回。
  3. 不要把同一个 START 在四处无声当成四个独立打印故障。
  4. 保留已知可用普通控制码；判断 START 是否成功，要看它是否完成产品切换，不只听它自己是否重播。

F. 官方书籍没有声音

  1. 按书籍产品编号重新取得对应官方音频。
  2. 使用官方音频页 / Manager 或底座官方流程。
  3. 查官方说明与排错页；不要用 DIY YAML 猜官方映射。
  4. 仍失败时联系官方支持，并提供笔型号与产品信息。

10 · Release discipline

版本、回滚与 QA 清单

把每次发布当成一个不可拆分的 release：PDF、GME、registry、source map 和校验清单必须指向同一版本。

发布包建议包含

  • A4 Sessions PDF（可见版本号）
  • 唯一的当前 GME（文件名含版本或稳定名称）
  • 项目 YAML 与稳定 codes registry
  • audio source map 与来源/许可记录
  • 构建日志、tttool 版本、脚本数量
  • SHA‑256 校验清单与 ZIP 完整性结果
  • 实体测试记录与仍待测试项目

发布门槛

  • 无重复 Product ID 冲突
  • 历史 OID 未被重排或复用
  • 所有引用音频存在且可解码
  • PDF 每页已渲染检查
  • 下载链接与文件名一致
  • 诊断页在目标纸面通过
  • 私人文件与公开站点已分离

推荐版本规则

变化示例要求
修错字/排版，不动音频映射v1.0 → v1.0.1重做 PDF QA；OID 与 GME 可保持，但发布记录要写明。
追加 Session / OID / 音频v1.0 → v1.1更新兼容旧码的 GME、registry、source map，并实体测新增码。
不兼容的产品重构v1.x → v2.0原则上分配新 Product ID；旧纸、旧 GME 与迁移说明长期归档。

回滚不是删除：保留上一个实体通过版本的完整副本。若新版异常，从笔根目录移走新版 GME，复制上版，再用上版诊断页确认。不要覆盖本地唯一副本。

11 · Rights & privacy

版权和隐私：纸、声音、网页分层处理

可以公开的

自己的方法说明、自己创作且愿意公开的学习页、明确允许再发布的文本/录音，以及符合许可条款并保留所需署名的材料。

默认只留本地的

个人录音、学习进度、错题、购买教材内容、内部材料、未经确认权利的音频，以及包含个人经历或敏感事实的 Session。

第三方与 TTS

第三方材料“能下载/能播放”不等于可以重新打包发布。逐项核对许可、署名、衍生作品与商业使用条件；TTS 也要核对供应商条款。

公开前清扫

删除本机路径、设备标识、网络接入信息、账户、构建缓存与私人 source map。公开下载物单独做隐私和许可检查。

本项目的发布边界：网页说明书与有权公开的西语 A4 学习页可以公开；包含个人固定音频和完整映射的西语 GME 是个人本地包，不提供公开下载。其他科目的教材型内容默认也保持私有，除非逐项证明可公开。

12 · Work with Codex

让 Codex 帮忙时，给它明确的边界

Codex 可以整理材料、生成版式、维护映射和运行检查；实体打印与点读结果仍需由人记录。下面的提示可以直接改主题后使用。

新增一个 Session

请基于现有 OID registry 新增一个 A4 点读 Session。只追加编码，不修改或复用历史 script code；保持当前 Product ID 与旧纸兼容。先列出材料来源和版权边界，再生成分段音频映射、A4 PDF、更新后的单一 GME、source map、校验清单和实体测试页。软件通过与实体通过分开报告。

把一组网页练习变成纸面 Sessions

盘点这些网页中已有的固定文本与固定音频，把它们按“看懂→点听→跟读→遮住提取→点读自检→迁移”重组为 A4 Sessions。保留来源指针，不把浏览器临时语音误当成可离线固定点读的音频。普通码按已验证的打印参数，START 用 3×3、22 mm；逐页渲染检查，并输出缺口列表。

诊断一张不稳定的打印页

请只诊断，不先重建整包。我会提供纸面勾叉结果、打印设置、PDF 版本和笔内 GME 文件名。请区分：设备/装包问题、同 PID 冲突、OID 打印问题、脚本映射问题。保留旧 OID，为疑似坏码追加 replacement 做 A/B 页；不要把同一个重复码算作多个独立样本。

给 Codex 的四样证据：当前 PDF、当前 GME 的版本/校验值、稳定 registry、实体纸上的勾叉扫描。缺少其中任何一项，都要明确说“未验证”，不要猜。

13 · FAQ

常见问题

GME 里的音频是在使用时联网播放吗？
不是。GME 已复制到笔后，点读是本地离线播放。底座 Wi‑Fi 主要服务官方音频下载，不是每次点读的网络播放器。
本地 GME 应插笔上的口，还是底座上的口？
插笔身的数据口并连接 Mac。底座接口用于底座供电/充电及官方无线下载流程，不作为本手册的本地文件复制入口。
能不能通过蓝牙把本地音频传进笔？
本工作流不支持，也不依赖蓝牙传文件。使用支持数据传输的 USB 线，把构建好的 GME 复制到笔根目录。
底座 Wi‑Fi 能上传我自己的 MP3 吗？
不要这样假定。官方底座流程面向官方产品音频；DIY 内容要先构建为 GME，再通过笔身 USB 复制。
可以直接把 MP3 拖进笔里，然后点纸播放吗？
不可以。纸上的 OID 要通过脚本映射到音频；要用 tttool 等流程把 Product ID、OID 脚本和音频构建成 GME。
为什么四个 START 都不响，其他码却响？
四个位置印的是同一个 Product OID，不是四个不同码；而 tttool 社区已记录，自制包处于激活状态后，同一 Product OID 可能成为无动作码。普通脚本码大量能响，已经证明 GME 主流程可用。正确复测是先用官方产品启动码切换出去，再点本册 START，然后点 listo，看是否成功切回。
--pixel-size 2 既然成功，为什么 START 用 3？
这里的 2 / 3 是每个微点占用的栅格像素边长。START 是入口和诊断关键点，值得用更保守的 3；普通内容兼顾页面密度，可使用已验证的 2。
能把两份相同 Product ID 的 GME 一起放在笔里吗？
不要。一个 Product ID 在笔中只保留一份当前 GME。新版应把旧脚本与新增脚本合并，而不是并存两个同 PID 包。
新增内容后，旧纸会失效吗？
只要 Product ID 不变、旧 script code 映射不变且新版 GME 继续包含旧脚本，旧纸就应继续工作。这正是 append-only registry 的意义。
网页里的浏览器朗读能直接变成离线点读吗？
不能自动等同。浏览器临时合成语音必须先变成权利清晰的固定音频文件，再经过分段、映射、GME 构建和实体测试。
为什么 GME 不放在公开下载区？
个人包可能包含个人音频、完整映射或权利边界尚未逐项确认的素材。公开网页与私人运行包分离，更安全也更容易长期维护。
